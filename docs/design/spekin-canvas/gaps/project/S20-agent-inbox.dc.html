What it must show
  • Every background run lists here: interview turn, depth expansion, reference capture, ticket breakdown, verification intake, independent review.
  • The inbox sits beside the work and never covers it; the top-bar chip keeps counting when it is closed.
  • A run row shows type, id, step, tokens, time and credits, with Stop and Steer.
  • A steering note is accepted on every run, logged, and applied at the next step.
  • Runs that spend credits wait for Approve and reserve their maximum first.
  • Failed runs name the step that failed; Retry reserves again.
  • Finished runs link to their result (S18 report, S08 review).

Where it lives
Route: docked panel on any stage; ?inbox=1&run=RUN-0420 reopens it. Back and Forward never start a run.UI (TS/React): PRD names components/agent-inbox; OpenDesign todo and progress cards as pattern (Apache-2.0, commit e033aad).Core (Rust): run queue, steps, reservations, steering log, cap checks (R-ARC-1).Open for Enrico: whether Needs you also pings by email · retention of finished runs (30 days drawn).
States
  • All runs · Entry: Any stage > top bar: click the busy chip or the inbox icon. · Data: sample/parts/gap-d.mjs → GAPD_RUNS.
  • Steer a run · Entry: Inbox > Running > RUN-0420 > Steer. · Data: sample/parts/gap-d.mjs → GAPD_RUNS, GAPD_STEPS.
  • Approve a run · Entry: Inbox > Needs you > RUN-0417. · Data: sample/parts/gap-d.mjs → GAPD_RUNS.
  • Finished and failed · Entry: Inbox > Finished. · Data: sample/parts/gap-d.mjs → GAPD_RUNS.
  • Credit cap reached · Entry: Inbox while the project credit cap is used up. · Data: sample/meranti-yard.mjs → USAGE; sample/parts/gap-d.mjs → GAPD_RUNS.
  • Empty inbox · Entry: Inbox before any run has started. · Data: none (empty state).
Reference: the original UIOpenDesign (Apache-2.0, commit e033aad) is the main reference for the file and export pattern; patterns only. Spekin copies no brand, copy or assets.

## Method and evidence rules

- The list is the `s === "unmapped"` requirement cells emitted by `node tools/live/parity-export.mjs` on `origin/main` (`counts.unmapped === 80`). "Unmapped" there has one narrow meaning: the R-id does not appear as a value in `docs/design/spekin-canvas/maps-reqs.mjs` (`parity-export.mjs:128`). It is **not** a claim that nothing implements the requirement.
- Short requirement text below is condensed from the requirement's own definition in `inputs/Spekin-PRD-v0.2.3.md`. The parity page's `k` field is the *first line in the PRD that mentions the id* (`parity-export.mjs:70-72`), which for a few ids is a metadata line, so the definition row is the more faithful short form.
- Verdicts:
  - **map** — an existing `data-feature="F…"` element in `apps/web/src` already does the work. Evidence names the F-id and the file:line of the real element (not a comment, not a test). The lead applies these rows to `maps-reqs.mjs`; this card does not.
  - **core** — a server / core rule, not a screen. Evidence names the proving Rust or JS test (file + test name), or says "no test".
  - **later** — the PRD itself places the work in a later increment, slice or adapter. Evidence quotes the PRD line (with line number).
  - **gap** — nothing does it yet. Evidence says what is missing.
- `file:line` references were read on branch `imp-52-req-map` at the commit in the PR. Each one is a real element/test/line a reader can open.
